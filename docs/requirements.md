# Tasktap

The linked [interaction design](interaction-design.md) describes the resident Mac app. The [browser prototype](../prototype/index.html) uses fictional session activity for reproducible review.

## Product purpose

Catch a thought while the user is speaking or drawing. Preserve it, connect it to the right local project or existing agent session, and bring a decision back to the user at their Mac. The user can finish speaking before choosing a destination. The installed agents own planning, tool use, and execution.

| C1 | A deliberate shortcut or button begins a capture. Support voice, typed input, and a sketch in one capture. Allow review, edit, cancel, and retry. | Canceling a capture produces no agent message. Loss of microphone access leaves typing and drawing available. |
| C2 | Preserve the original transcript and drawing alongside an editable handoff. Separate facts, ideas for later, questions, instructions, and constraints within a single ramble. | “Remember this curve, maybe animate it later, ask Claude where it lives” saves a note and sends an investigation request. | R1 | Index explicitly configured workspace roots, initially ~/projects. Record folder and worktree identity, aliases, and a short project description. Refresh on changes. | The alias “wallpaper” resolves to the registered workspace. If its folder moved, offer to locate it before launch. |

| R3 | A unique eligible match may route directly with a visible destination. Multiple plausible matches require a choice. | Two sessions doing lighting in different worktrees prompt a choice showing project, task, and agent. A note can be filed without dispatching an agent. |

| N4 | The notch is the daily interface. Capture, review, routing, nudge, decisions and completion summaries must work with the workspace window closed. | Launch to the notch, select a project, resolve a decision, and resume the foreground app. The workspace opens only on an explicit request. |
| N5 | Keep a persistent macOS status item. Offer capture, pending requests, workspace, Micro controls, notification settings and quit. | The same commands work on an external monitor without a camera cutout. The compact panel stays inside its visible frame. |
| N6 | Support opt-in macOS notifications for requests and completions with exact-ID actions. Honor system authorization and Focus. | “Review in notch” opens the named request. Dismissal defers. A closed request produces a stale notice and leaves the next request alone. |

| K1 | Register global capture and decision shortcuts; expose conflicts in the menu. | H2 | Route Micro, keyboard, pointer and voice to the same request and session IDs. | H3 | All decision and discussion flows work with the Mac alone. The Micro adds direct, request-scoped Yes, No and Talk actions. | Unplugging the pad or disabling native lighting preserves the question, discussion and keyboard controls. A late key event carrying an old request ID has no effect. |
| H4 | Size the amber rim to the active display’s reported camera exclusion. | H5 | Offer opt-in green and red cues on two independently lit Agent Keys. Clear them whenever their direct actions are unavailable. | Discuss, dismiss, resolve or quit clears the pair. The menu-bar count and visible labels convey decisions independently of color or connected devices. |
| N8 | Present agent-originated questions and ask for missing routing information automatically. Attach the follow-up, draft and final answer to the original session and decision. | Sending or dictating a follow-up leaves the request pending. Sent follow-ups and drafts survive relaunch. |
| N9 | Offer separate opt-ins for routing narration and completion narration using the selected available voice. | Routing narration reads a short progress update and the reviewable handoff. Muting it leaves every written status and reference available. |

### Project visibility and integration scope

Projects opens with folders that have queued work, a running turn, or an outstanding question. A discovered folder, an idle session, or a timestamp is insufficient evidence of activity. Show idle projects includes the full available list. Start session opens a brief scoped to the selected folder and submits only after review. A spoken project name still resolves against the full catalog.

Every new task must open an interactive agent in the selected terminal. A user can open that same session from Sessions and type, interrupt or approve work directly. Routing credentials belong only to capture preparation. Show the reviewed prompt, routing evidence and destination, and retain them with the delivery receipt. A follow-up must address the existing conversation or explicitly offer to copy the text for manual submission. First-run setup requires no lifecycle hook installation. External state observations carry the capabilities of their actual source.

## Current implementation

The resident Mac app uses Apple Speech, local project and task matching, and Apple Foundation Models for unstructured captures on supported Macs. Each handoff is reviewable. Tasktap delegates execution to installed CLIs and keeps an ordered queue and receipts on disk. Local notes and sketches can remain in Scratch or be linked to a project. See the [implementation and setup guide](../README.md) for transport and storage details.

The standalone browser preview uses fixtures for reproducible design and interaction tests. The [controller guide](controls.md) includes the hands-on checks for physical lighting, notification delivery and shortcut conflicts. Open work includes broader routing evaluation, live mid-turn steering for managed agents and native permission forwarding across all providers.
