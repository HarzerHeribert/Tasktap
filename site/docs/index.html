How it works

A short guide to Tasktap on the Mac and on Windows: what Tasktap does, and where each part of Tasktap is. What this guide leaves out is listed at the guide’s end.

Capture

Press ⌃⌥Space in any app. The notch opens on one line: type the task and press ↩. Or hold ⌥Space in that line and talk, and let go to send it.

The window’s Home starts with the same field, and ⌘N opens the field from a workspace. The field says where the task will go: Auto, where Tasktap finds the project, or a folder or the Scratchpad you choose, with the choices on ⌘K. The field’s key says what ↩ will do: Start, or Save for later. A task saved for later waits on Home until you send it to a folder.

Beside the place, the field names the agent that runs the task, and ⌘J lists the agents. In the window, a third control sets the task’s weight: Light, Standard or Heavy, on ⌘L. A weight starts the task on the model and the effort you gave the agent for that weight in Settings › Agents, and counts for that task alone; the next task is Standard again. The control appears once the agent has a model or an effort filled in, and not for a follow-up, which stays on the model of the session the follow-up continues. The notch has no weight control, so a task from the notch runs on Standard. A session’s details on ⌘I name the model and the effort the session ran on, and the weight where you chose one.

On the first start, a welcome stands where Home would in Tasktap’s window. One of four steps is in view at a time. Each step has one main button, which ↩ presses, and Skip, which moves on and leaves the step open; esc closes the welcome. While a step is open, Home shows a quiet line, Finish setup, that returns to the first open step, and Settings › About, at Welcome, has Show again.

Your projects
Tasktap searches as the step appears: the folders your agents worked in and the usual places for projects, and your home folder when those hold none. Each project found has a switch, and Search in a folder… adds a folder of your own.
Your agents
The agents installed, with Sign in for an agent that is signed out, and New tasks start with, which names the agent that runs new tasks.
Finding the project
ChatGPT, after Sign in with ChatGPT; Your agents; and, where an Ollama server answers on the computer, Ollama, which opens the address, the model and the key of a model of your own. Choosing a way is your agreement to what is sent, and What is sent is a click away.
Talk instead of typing
The key to hold, Listen, which shows the microphone’s level and records nothing, and where speech becomes text, with Download for the Mac’s own model.

Placing and the brief

Give a task without choosing its place, and Tasktap finds where the task belongs: which project, and whether an agent already at work there continues, a new run starts, or a new project begins. A model decides: your ChatGPT plan after Sign in with ChatGPT, in one direct call with no agent started; a model of your own at an address you give, such as Ollama or LM Studio on your own computer or a hosted service; or the smallest model of your Claude Code, Codex or Antigravity. Settings › Placing sets this up. Find the project for each task is the one switch, and Who finds the project lists the ways in the order they are asked, the first asked first: ⌥↑ and ⌥↓ (Alt+↑ and Alt+↓ on Windows), or a drag, move a row, and Space switches a row on or off. Signing in with ChatGPT, setting up your own model and switching an agent on are each your agreement to what is sent; under Details, What is sent and The instructions they follow show the list and the model’s instructions in full. Without your agreement, a task goes to the folder or the session the task names, and Tasktap asks you about every other task.

A model of your own needs an address, a model name and, if the server asks for a key, a key. A server on your own computer or network can use plain http; any other address must be https. Where an Ollama server answers on the computer, Settings › Placing offers the server with its address filled in.

To decide well, the model is sent the task in your words; up to 8 likely projects, each with its names, one line about the project, 5 earlier tasks and the folder names at the project’s top; the sessions in those projects, each with its first and last request, the agent’s state and the start of what the agent last answered; and your 3 latest tasks in those sessions with how each ended. The earlier tasks include requests you gave Claude Code or Codex outside Tasktap, so the first tasks you give Tasktap are placed by what you did before. A word that looks like a key, a token or a password is left out, also from the task. A long task you place yourself is read too, for its summary, and nothing else is sent with that task.

In a workspace the field names that workspace, and in a session’s view that session, so a task typed there goes there at once. Choose Auto in the field to let the model decide instead.

A task is placed among every folder Tasktap knows, not only the folders you opened. The first start and Settings › Projects learn those folders from where your agents worked, with a switch for each agent at Find projects in your agents’ history, and from folders you add at Folders to search for projects. The search reads folder names and each project’s README, package file and Git remote, and, for Claude Code and Codex, the first request you typed in each of a project’s latest runs, and nothing else that was said there. What the search learns stays on the Mac until you allow placing.

The same model writes the brief, which is what the agent receives. The brief states the goal, the limits you gave, and what counts as done if you said so. The brief adds nothing you did not say, and your own words always travel with the brief. A short, clear task goes on as you said it.

While you write or speak a task with Auto in the field and placing on, the line under the field shows where the task would go: the project, and the session the task continues or a new run. At first the line shows Tasktap’s own guess from your projects’ names, quietly. From the third word on, when ChatGPT or your own model is first in Who finds the project, that model’s answer takes the guess’s place in full tone, and ↩ takes the answer once the place has stood for half a second: the task starts there with no second question. Before then, the task is placed as any task is. When the model is torn, the line says “1 of 3”, and ⌘G shows the next place, which ↩ then takes at once. Settings › Placing, at Show the target while you write, turns the model’s answer off: the words so far are then sent nowhere, and only Tasktap’s own guess shows.

Once placed, the task waits under the field. The line shows the project and whether a session continues or a new run starts, with the session’s task under the project. With the field empty, 2 switches between continuing and a new run, Undo on ⌘Z brings your words back to the field, and ↩ starts the task at once. A task the model placed waits up to three seconds after the decision appears. A task you placed yourself waits five seconds, or the time you set at Wait before an agent starts a task in Settings › Tasks. The lit line above the task runs out with the time that is left.

When the model is torn between places, nothing starts by itself. The line shows the likeliest place on ↩ and the other places on 2 and 3, and waits for your key. The notch opens by itself to show the line, and a notification comes when a full-screen app or a presentation hides Tasktap.

When nothing fits, or no model can be reached, Tasktap asks you, with your words first: “Which project is this task for?” The question offers only the projects your task names or clearly describes, each with the reason, then Another project…, the Scratchpad and Keep for later, each on its number. A task that begins something new gets New project with a proposed name and place as the first answer, and the folder is made only on that answer’s key. When the question offers no project, Open or create a folder… comes first; before you have any project, the question reads “Where should the agent work?” Another project… turns the answers into a field that finds any project Tasktap knows by name, with Open or create a folder… as the field’s last row; that row opens the system’s folder panel, and the folder you choose opens as a workspace and receives the task.

A task never answers an agent’s question by itself. When the session a task would continue is asking you something, the task goes to the same question card, which names what the agent asked. If the agent’s question takes your own words, the first answer sends the task’s words as your reply.

Questions

While agents work, the folded notch shows counts: working, needing you, finished. When an agent needs an answer, the notch opens by itself and shows the question in full.

Choices are on 1 to 9. A yes or no is also on Y and N. T opens a reply in your own words. With several waiting the notch says which one you see, “2 of 3”, and → shows the next.

From any app, ⌃⌥J goes to a waiting question, and ⌃⌥Y and ⌃⌥N answer yes or no without leaving what you are in; on Windows they are Alt+Shift+J, Y and N. Tasktap takes them only while a question waits, and Settings › Tasks records others. They are keys by their place: on a German keyboard the second is the key that says Z.

The same question stands first on Home and under its terminal in the workspace, so you answer it wherever you are. Some questions can only be answered in the agent’s own terminal; the card then leads there. Which agent asks where is listed under Agents.

Results, Keep and Discard

A finished task comes back as a result: a summary, and its changes when it ran in its own copy of the project.

On Home, the newest three results you have not opened are cards, and older results are rows of one line. A card shows your words, the start of what the agent answered, the agent’s mark, the project, the time and the changes, with Open, Follow up, Try again when the task failed, and Keep, Discard and Review changes where changes wait. Resting the pointer on a row, or moving the keyboard onto a row, shows the row’s card as a peek when the row has cut something. With the keyboard on a row or a card: ↩ opens the session, K keeps, D discards, R reviews the changes, F follows up (cards only) and I shows the details.

In a git project that already has work running, a new task gets its own copy (a git worktree) and its own branch, so two runs cannot overwrite each other. Settings › Projects, in a project’s details at Where its agent works, can give every task its own copy, or none. Keep adds its commits to your branch by a fast-forward, the same one you would run yourself; if your branch has moved on meanwhile, by a merge commit, and if the two conflict Keep changes nothing and names the files. Discard removes the copy. Review changes shows the diff first. In the notch they are on ↩, D and, to open the session, O.

Tasktap never deletes or rewrites anything outside its own folder and its own branches. If something unexpected happens it stops and reports the real state. Folders without git run in place.

The sidebar lists Home and every open folder as a workspace, with its sessions and the state of each. A workspace holds real terminals in panes with tabs.

Drag a divider to resize panes. Drag a tab onto a terminal to share its space, or onto tabs to join them. A tab’s right-click menu has the rest, including Keep running in background: the session leaves the panes, stays in the sidebar, and a click brings its terminal back where it left off.

A workspace can have a window of its own: the window icon beside its row in the sidebar, Open in New Window in the row’s right-click menu, or ⇧⌘N while the workspace shows. The new window holds that workspace alone, with no sidebar, named for the project, and the workspace’s terminals go on as they were. Home, Settings and opening a folder stay in the main window, where the workspace’s row now carries a window mark and a click brings the window forward. Closing the window puts the workspace back in the main window, and the workspaces that had windows when Tasktap quit come back in them at the next start.

A link in a terminal is one while ⌘ is held. ⌘-click on an address of this Mac, a picture, a PDF, a page or Markdown shows it in a preview at the terminal’s right, and an agent can show what it made there with tasktap preview. A preview reaches nothing of the app and loads nothing from the network.

Quitting the app does not stop a session. The core keeps running for as long as a terminal runs.

Agents

Tasktap starts eleven agents: Claude Code, Codex, Antigravity, OpenCode, Pi, Qwen Code, Goose, Crush, Droid, Copilot and Aider. You install each and sign in to it yourself, on your own subscription; Settings › Agents shows which are installed and signed in, and, at New tasks start with, which agent runs new tasks. Any other agent that runs from a command line can be added there by its command, such as goose run -t {prompt}. To start one of Tasktap’s agents your own way, such as caffeinate -i claude, write that command in the Start command field of the agent’s details, which the chevron on the agent’s row opens in Settings › Agents; with the field empty, Tasktap starts the agent as always. For Claude Code, Codex, Copilot, Pi and Antigravity, the same details have a row each for Light, Standard and Heavy, where a model and, except for Antigravity, an effort can be written; a field left empty uses the agent’s own, and a start command of yours that names a model or an effort wins over these rows.

Claude Code, OpenCode
Questions, and requests to run a command or change a file, are answered from the notch, Home or the workspace.
Codex, Copilot
Their requests are answered there too; their questions in their terminal.
Antigravity, Pi, Qwen Code
What they ask is shown, and answered in their terminal.
Goose, Crush, Droid, Aider
They run one task to its end and ask nothing on the way. A follow-up waits for that end. Aider ends the same way whether it did the work or not; its terminal says which.

Tasktap never writes to an agent’s own settings: what it needs for a run is given to that run, from Tasktap’s own folder.

Voice

Hold ⌥Space in the capture field or in a reply, or press and hold the microphone. The key works while Tasktap is in front; in an empty field, letting go sends the task, and E before letting go keeps the words to edit. A short click on the microphone keeps it on until the next click. While it records, the light on the mark follows your voice.

Speech can be turned into text on the Mac itself. Settings › Voice, at Where your speech becomes text, downloads the model once: Whisper large-v3 turbo, 574 MB, checked before it is used. After that what you say is written while you speak, a sentence or two behind, and sent nowhere; nothing of it runs while you are not speaking. It was tried in German and English, and in both mixed in one dictation, as a developer speaks them.

Or speech is turned into text by a service you choose: OpenAI, Groq or another server, with your own key. Before anything is stored, the sheet shows exactly what is sent and where. A recording is at most five minutes. You can name the languages you speak, as a hint.

On Windows

On Windows on x64, Tasktap works as this guide describes, with the differences named in this section. Windows has no notch: a small tab hangs from the top edge of the screen and opens into the same sheet, and an icon by the clock says what waits and opens it too. The tab hides while a full-screen app or a presentation runs. Settings › Tasks, at Display that shows Tasktap’s tab, chooses its display, or None turns it off.

Keys follow one rule: Ctrl stands where the Mac has ⌘, and with a letter Shift is held too, so Ctrl and a letter alone stay the terminal’s. New terminal is Ctrl+Shift+T, and Find Ctrl+Shift+F; the lists of agents, places and weights, and the next place for a task, are Ctrl+Shift+J, K, L and G. A few keys are Windows’ own: Split right is Ctrl+Shift+D and Split down Ctrl+Shift+E, Open workspace in new window is Ctrl+Shift+M, and Undo is Ctrl+Z. With a digit or a comma, Ctrl stands alone: Settings is Ctrl+, and its sections are Ctrl+1 to Ctrl+8. The capture key is Alt+Shift+Space, and the keys that answer a question from any program Alt+Shift+J, Y and N, since many keyboards read Ctrl+Alt as AltGr; hold to talk is Ctrl+Space.

On Windows, Tasktap starts Claude Code, Codex and any agent you add; the other nine built-in agents run on the Mac only. Speech on Windows goes through a speech service. Tasktap for Windows needs an x64 processor, and the PowerShell line refuses a computer with an ARM64 processor. The Windows installer is not code-signed, so SmartScreen stops a copy downloaded in a browser until you choose More info, then Run anyway; the PowerShell line under Install downloads the installer, checks the installer’s SHA-256 and installs Tasktap for you alone, without that stop.

Settings

⌘, opens Settings, its sections at its left in this order, on ⌘1 to ⌘8. Each row says what you decide, and a sentence in the window’s foot, while the row has the pointer or the keyboard, says what changes for you.

Tasks
Key to start a task, from any app. Open Tasktap when the computer starts: it then opens with no window, only the notch (on Windows its tab and icon), so the keys work from the start; System Settings lists it under Login Items, Windows under Startup apps, and you can remove it there too. A copy you built yourself cannot be opened that way, and says so. The keys to go to an agent’s question and to answer Yes or No, from any app, which Tasktap takes only while a question waits. On Windows, the display that shows Tasktap’s tab. Return key when writing a task: sends the task, or starts a new line. Wait before an agent starts a task: no wait, 3, 5 or 10 seconds, at least, since finding the project can take longer; ⌘Z takes it back meanwhile. Delete finished tasks after: never, 30 days, 90 days or a year, with their answers and the terminal’s history.
Agents
Which agents are installed and signed in, which agent runs new tasks, what an agent may do only once you let it, the command that starts each agent, its Light, Standard and Heavy models, and the agents you add. Check which agents are signed in.

Find the project for each task, the one switch. Who finds the project: ChatGPT, with Sign in with ChatGPT or Sign out; a model of your own, with Set up… or Change; and your agents, each with a switch, in the order they are asked. Details: What is sent, and The instructions they follow.
Projects
Find projects in your agents’ history, a switch for each agent. Folders to search for projects, with Add a folder… and Search again. Your projects, with a field to find a project by name; opened, a project shows what Tasktap knows of the project, the names the project goes by, and where its agent works: on its own copy when another agent is working there, always on its own copy, or in the project itself, where two agents at once can overwrite each other’s changes. Terminal
Font, text size and space between lines in terminals. Bold text in brighter colours, and text that is hard to read adjusted.
About
The version, and Check for new versions: on, Tasktap asks GitHub when About opens and at the first task of a day; off, it asks only when you press Check now. A new version is installed only when you say. Welcome, with Show again. What Tasktap keeps and what it sends, the check for a new version at GitHub among it while it is on, and the licences of what it ships with.

Effects

Home has soft light and a band of chrome, and the foot of the sidebar a few chrome glyphs. At rest they are still and cost nothing. They move only while something goes on: agents working, a question waiting, your voice.

One setting covers all of it: Full, Still, which keeps the picture and stops the motion, or Off, which draws none of it. While Reduce Motion or Low Power Mode is on, Full behaves as Still; on Windows, that is while animation effects are off or the PC saves power.
